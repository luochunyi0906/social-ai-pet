# 看山有伴 v0.9.9 知乎直答与会话记忆

## 启动和配置

直接打开 `release/看山有伴.app`，进入营地「和刘看山聊聊」，确认界面显示 `zhida-fast-1p5` 和 `developer.zhihu.com`。写好消息后，勾选发送当前文字与必要会话上下文的确认框，再点发送。直答请求可能消耗平台额度。

当前 Mac 上，林间预览的主进程可在当前配置未声明该字段时，只读复用本机旧项目配置中的 `ZHIHU_ACCESS_SECRET`。带临时用户目录的测试和开发不会自动读取个人旧配置。换机、更新密钥或选择备用模型时，通过项目的 `Configure-Model.command` 打开当前配置文件，在本机填写：

```ini
CHAT_PROVIDER=zhida
ZHIDA_MODEL=zhida-fast-1p5
ZHIHU_ACCESS_SECRET=
CHAT_CONTEXT_TOKENS=4096
CHAT_REPLY_TOKENS=384
CHAT_TIMEOUT_MS=90000
```

独立应用的文件位于 `~/Library/Application Support/看山有伴-林间预览/model.env`，开发模式用项目 `.env`。修改后重启应用，或在模型设置点「重新检查配置」并重新打开对话面板。备用模型名为 `zhida-thinking-1p5`。当前模型由配置明确指定，切换时不会把密钥发往其他服务。

显式回退可使用 `CHAT_PROVIDER=llama.cpp`（本机模型自动启动时保持 `CHAT_BASE_URL` 空白）、`CHAT_PROVIDER=ollama` 或 `CHAT_PROVIDER=existing`（沿用 `MODEL_*` 模型配置）。应用包级回退可退出桌宠并打开修改前的备份。会话文件格式仍为 v1，可随已有版本使用同一份用户数据。

## 实现与会话存档

Electron 渲染进程通过已有白名单 IPC 请求 `desktop/main.cjs`。主进程经 `desktop/chat-model.cjs` 和现有 `desktop/model.cjs` 调用 `POST https://developer.zhihu.com/v1/chat/completions`。每次生成秒级时间戳并从本机配置提供 Bearer 鉴权。请求体只有 `model`、`messages`、`stream`，使用 `stream=false`。完整回答从 `choices[0].message.content` 读取，推理字段不用于聊天或存档。

独立应用在 `~/Library/Application Support/看山有伴-林间预览/chat-v1.json` 保存原始轮次、角色、消息和会话 ID、时间、结果状态及摘要覆盖边界。记忆随本会话保存，关闭面板、原生进程退出再开均可读取。当一条回复未完整完成时，后续请求只使用已完成的问答；用户原文仍可查看或原地重试。清空操作仅作用于当前会话的轮次和摘要。

每次提问使用角色说明、已有历史摘要、近期完整的用户和助手文本，以及本轮消息。直答兼容模式把摘要作为明确标注的历史资料，放在第一条保留的用户消息前；若预算没有留下早期原文，放在当前用户文本前。这样可以保持角色交替，同时避免丢掉独立的摘要数据。测试中观察到连续的两个 user 消息有时导致直答漏读单独的摘要。

`CHAT_CONTEXT_TOKENS` 和 `CHAT_REPLY_TOKENS` 是应用内的估算预算及回答预留。预算使用保守的 UTF-8 字节估算加角色开销，默认按 4096 减去 384 估算历史可用空间。这些值不是知乎承诺的上下文或输出上限，也不会作为请求参数传给知乎。达到预算后调用当前直答模型压缩较早的已完成用户原话，尽可能保留近期完整轮次。摘要覆盖边界用消息 ID 记录，原始轮次独立留下。用户更正先以当前原话进入真实请求；该轮完成后，后续摘要采用当前值。摘要仅作参考资料，模型可能遗漏细节。

| 文件 | 负责内容 |
| --- | --- |
| `desktop/model.cjs`、`desktop/chat-model.cjs` | HTTPS 请求、知乎模型默认配置、正文解析、错误分类、历史格式 |
| `desktop/main.cjs`、`desktop/local-chat.cjs` | 现有聊天 IPC、主进程读取凭据、显式保留本机模型 |
| `desktop/chat-session.cjs` | 滚动摘要与覆盖边界、原始会话及错误状态 |
| `.env.example`、`src/types.ts`、`src/ModelPanel.tsx`、`README.md` | 配置与状态提示 |
| `tests/chat.test.mjs`、`tests/desktop-chat.integration.mjs`、`tests/desktop-direct-chat.integration.mjs` | 传输和会话回归、真实桌面验收、本机回退验证 |
| `tests/desktop-woodland.integration.mjs` | 原有模型的模拟测试显式选择回退服务 |

A 的实际第二次请求是 system → user → assistant → user，上一轮姓名、项目和日期原文与上一条真实助手回复均在载荷里，本轮问题只写一次。D 的补测重新打开原生应用进程，读取并逐项比较同一测试会话，再实际发出知乎请求。E 的补测把应用预算调至 3540，真实请求生成摘要，保留下来的近期问答和摘要同时进入下一次调用。原始记录逐项比较一致。

早期的连续请求触发 HTTP 429，当时有多个用例被拒绝。后续验收降低请求速度。一次初版摘要已保存正确事实，最终请求却漏读了摘要。修复输入格式后，在更紧的 3120 测试预算里回复已正确，但没有保留近期原文进入模型输入。用 3540 复测确认两者同时传递。整套连跑中的重启步骤曾在发出 HTTP 请求之前被取消，改用独立的原生进程补测后取得模型返回。还观察过模型在回答最新日期时复述旧日期的更正过程，最终验收要求只列当前有效值。

82 项单元及宿主检查通过。9 项独立桌面模拟检查通过，涵盖 HTTP 503、迟到回复、取消后重试、新会话隔离以及退出时未完成的请求。它们仅验证故障和状态逻辑。鉴权和额度错误使用无真实凭据的 HTTP 401、403、429 及业务码响应测试。备用思考档通过配置校验，本轮未使用它跑线上用例。显式切回本机 Qwen 的独立应用实测也通过，复用了已有服务，退出测试应用后该服务继续运行。

真实的测试证据保存在 `artifacts/chat-real-zhida.json`。D 和 E 的独立复验在 `artifacts/chat-real-zhida-restart.json`。早期失败证据为 `artifacts/chat-real-zhida-rate-limit.json` 和 `artifacts/chat-real-zhida-first-paced.json`。模拟报告为 `artifacts/chat-fixture-zhida.json`。记录只包含虚构的测试输入与脱敏的请求描述。

日常遇到 429 时，请稍等再手动重试。测试等待间隔用于避免集中调用；正式应用不会自动重试，也不会自动切换模型。紧预算或较长摘要可能挤掉更多近期原文，较早记录仍可在本机会话里查看。

最终应用已放回 `release/看山有伴.app`，通过 Mac 本地签名校验。正在运行的窗口可能含草稿，需要退出并重新打开后才会载入更新。
