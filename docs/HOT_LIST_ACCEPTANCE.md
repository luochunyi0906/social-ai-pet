# 今日好奇心 · 知乎热榜
2026 年 11 月 19 日 · 看山有伴 · 有图示例及真实数据独立验收

## 使用方式

打开 `release/看山有伴.app`，点击刘看山进入营地，再打开「好奇心山洞 → 今日热榜」。这份发布包适用于现有的 Apple 芯片 Mac 环境。右上角「推送设置」可开启每日提醒、修改提醒时间、选择 3／5／10 条速览和查看视觉示例。每日提醒默认关闭，默认时间 09:00、速览 5 条，按设备时区执行。完整榜单最多 30 条。

实时页面沿用本机 `ZHIHU_ACCESS_SECRET`；设置入口提供配置及刷新。页面可在阅读当前缓存时发起刷新，失败保持上次真实获取时间。有效缓存为同一设备自然日内且取得不足 30 分钟。聊天请求「给我看知乎热榜前 10 条」时取共享榜单的前 10 条。随后说「第二条讲了什么」，会按本会话最后展示的榜单定位，并把对应标题、可用摘要和链接交给直答。每次列表快照随该轮聊天写在本机，后台刷新不改变旧列表序号。

## 接口、Skill 与状态

官方原件在 `skills/hot-list/upstream/`。原脚本 2.0.0，使用 Python 3 标准库，命令入口为 `python3 scripts/hot-list.py '{"limit":10}'`。脚本读取 `ZHIHU_ACCESS_SECRET` 并允许端点环境变量覆盖，通过 GET 输出原始 JSON。HTTP、网络或解析错误以非零退出，业务 `Code` 仍由调用者核对。ZIP 和原件 SHA-256 记录在同目录 `manifest.json`。[知乎热榜官方 Skill](https://developer.zhihu.com/download/hot_list_skills.zip)

适配版运行于随包提供的 Electron 主进程。保留官方的 Bearer、秒级时间戳、输入 `limit` 映射到 HTTP `Limit` 和返回字段。适配增加了严格 1–30 校验、固定官方目标、有界响应、取消、业务错误映射及链接校验。包内资源为 `Contents/Resources/app/skills/hot-list/`，无需额外 Python 或 Shell。页面、提醒和聊天共用服务缓存和并发中的请求；榜单服务在网络读取时请求完整榜单，聊天和每日速览按用户所选条数取前缀。聊天的榜单由应用层明确路由，解释才走既有直答模型与会话记忆。

运行状态保存在用户配置目录的 `hot-list-v1.json`，包括最近一批榜单、实际获取时间、已读 URL、每日设置及当天提醒状态。收藏仍由现有花园记录、来源回执与种子机制维护。每天一次，正常模式轻提示，专注模式入口标记，睡眠静默留存。应用退出后暂停，回来只处理当天；没有安装系统后台定时服务。

## 实测结果

- 87 项单测通过。请求格式、1–30 上限、鉴权与频率限制、空列表、真实缓存、睡眠与专注策略、启动补当天及会话序号快照均有自动化覆盖。
- 独立签名 Mac 桌宠实际点击进入、手动刷新分别发出一条真实热榜 GET，均为 HTTP 200／业务 Code 0，分别于香港时间 03:09:21、03:09:26 取到 30 条，耗时约 1.0、0.5 秒。
- 聊天发送「给我看知乎热榜前 10 条」命中 03:09:21 的缓存，返回 10 条，未再次发热榜请求。「第二条讲了什么」确认使用当次第二条标题、摘要和链接，真实直答 HTTP 200，约 2.6 秒。
- 点击真实原文对 Electron 外部打开入口核对了服务返回 URL；验收拦截实际浏览器启动以避免抢焦点。真实收藏写入原手账机制，摘要、获取时间和待播种状态保留。示例链接与收藏操作只提示数据边界。
- 900 × 740 原生窗口拖动位移 19 逻辑像素，列表独立滚动，详情文字可选。600 × 620 示例可进入详情并返回。另用构造的 240 字标题、超长摘要和缺图数据检查截行与滚动。
- 断网、鉴权失败和限流为明确标注的注入测试，缓存与原获取时间保留。退出重启后恢复已读、收藏、提醒设置和当天已处理状态。同日打开页面时缓存命中，无重复请求。设备时间跨天与三种提醒模式通过受控时钟测试，尚未等待设备自然跨天验证。
- 脱敏记录在 `artifacts/hot-list/native-hot-acceptance.json`。它含时间戳、接口路径、返回数量、耗时和缓存命中结果，不含密钥或模型请求全文。
