# 看山有伴 · 自由活动与聊天表情验收

## 操作

- 营地的模型与检索设置中打开「自由活动」。默认关闭；启用后默认约每 90 秒空闲散步一次，最远 75 逻辑点，到达后停留 4 秒。间隔、距离、停留都可保存调整。
- 聊天输入框里的表情按钮打开 3×2 表情预览。选中表情，再点「发送表情」，消息显示为由自己发送。此操作只写本机会话。
- 聊天「连接与表情设置」显示当前服务、模型与自动表情开关。刘看山可在本次已授权回复时附一个表情。

## 移动调度

| 事件 | 后续行为 |
| --- | --- |
| 普通模式开启自由活动，停靠且持续空闲 | 选当前工作区内的短距离目标，顺序步行、停留、归位、冷却 |
| 手动移动角色或单独移动营地后松手 | 重新空等 15 秒，再按角色与最新营地的直线距离归位。超过营地所在屏幕可用宽度一半跑回，其余走回 |
| 靠近边界 | 用完整角色窗口的大小限制每个采样点。优先使用有足够空间的方向，抵达后停留 |
| 按下、拖动、菜单、展开营地、聊天和阅读 | 主进程取消自动目标及计时。空闲后重新计时，已脱离的角色先回营地 |
| 专注、暂停、睡眠、隐藏 | 禁止自动移动。手动挪动和模式状态分离 |
| 可用工作区或显示布局变化 | 将角色放回可见工作区并重新排定后续任务 |

## 表情协议

| 本地 ID | 表情 | 短文案 | 预览帧，从 1 开始 |
| --- | --- | --- | --- |
| emo_happy | 开心 | 给你鼓掌 | 4 |
| emo_laugh | 大笑 | 笑出声 | 4 |
| emo_curious | 好奇 | 让我看看 | 5 |
| emo_thinking | 思考 | 容我想想 | 3 |
| emo_expect | 期待 | 期待一下 | 4 |
| act_idle | 在听 | 我在听 | 1 |

以上 PNG 帧与提供的 ZIP 内素材逐字节一致。表情候选和短文案在 `desktop/chat-stickers.json`。回复可在最后另起一行放置 `[[LKS_STICKER:emo_happy]]`。知乎流式请求仍只发送 `model`、`messages`、`stream`。应用扣留可能的标记前缀，收到完整终止信号后才保存有效 ID。JSON 回包、其他模型通道的正文也经过同一解析。取消、失败和无效 ID 不产生贴纸记录。用户原话按文本处理，用户手动表情走独立的本地记录入口。

流式预览与最终回复使用同一个助手消息 ID。贴纸与正文同一条记录保存，重启后由本地资源恢复；向模型发送历史时以中文文字描述表情。贴纸播放器与桌宠身体的姿态、移动调度分离。

## 验收证据

- 知乎真实验证使用独立测试会话和虚构作业描述。真实服务 HTTP 200，实际走 SSE，在一次请求里返回白名单 `emo_happy`。本机原生聊天界面显示正文及贴纸，关闭重开后恢复，并检查 900×740 和 600×560 尺寸与手动表情归属。
- 模拟 SSE 分块与网络错误覆盖纯文字、非法 ID、取消、失败重试、同一条消息只保存一次、关闭自动表情、睡眠中回看、减少动态。旧聊天与授权逻辑使用工程测试回归。
- 单屏原生移动验证覆盖临近边界散步、聊天输入与阅读、专注、睡眠、营地和角色独立拖动、走跑归位。单测覆盖散步停留与冷却、菜单暂停和虚拟工作区改变。
- 未在两块实物屏幕上测试跨屏或热插拔。已有装扮无专用走跑帧时沿用本身外观。音乐与系统闹钟回归检查了入口与状态查询。
