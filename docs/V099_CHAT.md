# v0.9.9 桌宠文字聊天

## 启动

如果桌宠旧版正在运行，先退出。然后在当前 Mac 的项目目录双击 `Launch-Kanshan-Qwen.command` 可启动本机模型和独立应用。该命令使用与本项目相邻的本机推理资源，以离线模式监听回环地址。它在退出时关闭自己启动的模型进程，重新双击可重新加载模型并恢复原会话。

已运行 Ollama 时，可通过模型设置打开 `model.env` 并填写以下聊天配置，然后刷新设置并重新打开聊天，或重启应用。开发模式读取源码目录的 `.env`。

```ini
CHAT_PROVIDER=ollama
CHAT_MODEL=qwen3.5:9b
CHAT_BASE_URL=http://127.0.0.1:11434
CHAT_CONTEXT_TOKENS=4096
CHAT_REPLY_TOKENS=384
CHAT_TIMEOUT_MS=90000
```

Ollama 需先下载对应模型，例如 `ollama pull qwen3.5:9b`。也可使用 `CHAT_PROVIDER=llama.cpp` 连接本机的 `/v1/chat/completions`。启动 llama.cpp 时，把 `--ctx-size` 设为配置中的预算或更大，使用单槽 `--parallel 1`。两种本地服务地址均只接受回环地址。恢复原聊天服务时设 `CHAT_PROVIDER=existing`，沿用已有 `MODEL_*` 与 `ZHIDA_*`。聊天不会自动切换服务。

在营地中点「和刘看山聊聊」，每次发送前勾选发送同意。重新打开聊天会显示上次使用的会话。使用「新建会话」可从空白开始，使用会话下拉菜单可切回。「重试上一条」在同一条记录上重试。「清除本次会话」会清除当前会话的对话记录和摘要。

## 上下文与存档

- 完整记录以时间和消息 ID 写入本机用户数据目录的 `chat-v1.json`。记录区分等待、完成、失败、取消，按原顺序存储。文件使用原子替换及 0600 权限。
- 每次发送包含已有刘看山身份、当前会话已完成的近期消息及本次问题。失败和取消的记录仍可查看，模型上下文只使用成功的问答。取消后的迟到回复被丢弃。
- 默认窗口 4096，预留 384 输出。应用用 UTF-8 字节数加角色开销作保守估计，触发点可能早于模型实际 tokenizer。超过应用预算时，模型按时间顺序把较早的用户原话压缩成笔记，同时保留近期的用户及助手原文。用户最新说法优先，检测到明确更正且已有摘要时，会在本轮提交时更新摘要。历史原文继续保存。摘要调用失败会返回可重试状态。
- 会话之间没有共享记忆。上下文仅在用户按下发送、明确同意后发送至当前设置的服务。来自知乎的关联内容仅包含主进程验证过的标题、链接和有界摘要。推理字段不会显示在聊天中。

## 文件和回退

| 文件 | 作用 |
| --- | --- |
| `desktop/chat-model.cjs`、`desktop/model.cjs` | 本地聊天协议、原模型回退和输出预算 |
| `desktop/chat-session.cjs` | 会话、原子保存、重试、取消和摘要 |
| `desktop/main.cjs`、`desktop/preload.cjs`、`src/types.ts` | 聊天专用 IPC 与配置 |
| `src/ChatPanel.tsx`、`src/ModelPanel.tsx`、`src/main.tsx`、`src/style.css` | 在现有对话面板补齐会话和重试 |
| `Launch-Kanshan-Qwen.command`、`.env.example` | 启动本机服务与配置样例 |
| `tests/chat.test.mjs`、`tests/desktop-chat.integration.mjs` | 单测、独立应用验证及真实模型 A–F |
| `scripts/package-mac.cjs` | 排除个人聊天记录的独立 app 构建 |

服务回退使用 `CHAT_PROVIDER=existing`。应用回退则先退出 v0.9.9，再打开已验收的 v0.9.8。收藏、种植和原模型配置继续使用原路径。v0.9.8 不读取 `chat-v1.json`，后来再次使用 v0.9.9 时可继续该版本的会话。

构建使用 `npm run build` 或 `npm run package:mac`。包内不包含模型权重、API 密钥、收藏和聊天记录。

## 实机验收

2026-11-19，Apple M1 Pro、16 GB，macOS 26.6.2，测试对象为签名后的 v0.9.9 独立应用。真实请求走本机 llama.cpp 0.9.0-dev（6c01da627），模型为 Qwen3.5-9B Q4_K_M（服务元数据约 8.95B 参数），权重 SHA-256 为 `02d45dc1cf451ba2475ac33b301c2dd8f985abe4c182ce04a1f2f5bf0260278d`。此前 Ollama 安装包可下载，但当前运行权限限制了其默认目录初始化，因此用 llama.cpp 运行同一文本权重。

模型服务的窗口为 4096 tokens，应用预留 384 输出。E 项仅在测试中把应用预算调到 2880，触发较早历史的滚动摘要。推理服务窗口仍为 4096。接入时关闭思考输出。测试资料只进入独立测试会话。

| 实测项目 | 结果 | 真实模型输出或观察 |
| --- | --- | --- |
| A 即时追问 | 通过 | 你的项目叫「雪松」，演示日期是 12 月 8 日。这是你之前告诉我的信息，我会一直记着。 |
| B 隔几轮再问 | 通过 | 在这个会话里，你明确说过的信息是：姓名“小林”，项目名称“雪松”，演示日期"12 月 8 日”。 |
| C 使用更正 | 通过 | 姓名“小林”，项目名称“雪松”，演示日期"12 月 10 日”。 |
| D 原生应用退出重开 | 通过 | 项目名称是“雪松”，演示日期是 12 月 10 日。 |
| E 缩小应用预算强制摘要 | 通过 | 在这个会话中，你明确说过的信息是：姓名为小林，项目名为“雪松”，演示日期为 12 月 10 日。 |
| F 新建会话隔离 | 通过 | 在这个会话里，你尚未明确告知我你的姓名、所属项目名称或演示日期。 目前我们仅进行了关于“看山有伴”项目原则的对话，你并未提供具体的个人信息。如果你希望我记住这些信息，请直接告诉我，我会立刻更新记录。 |
| 真实服务发送后中止并原地重试 | 通过 | {"sameMessageId":true} |

E 项曾出现摘要被当成不可引用资料、旧值和新值混写、重复压缩时错误标记已知姓名为未知。F 项早期曾把桌宠的项目名当成用户自己的。调整后，早期摘要只取用户原话，已有事实在明确更正时才被替换，同时过滤互相矛盾的未知占位。完整原话继续保存在会话中。真实回复偶尔附带角色说明，表达风格留待后续调整。

真实请求共 12 条正常回复，调用中位数 2.3 秒，观察范围 1.4–6.5 秒。每次摘要请求 3.6–5.3 秒。正常聊天中生成速度约 20 tokens/s。

本机已下载约 5.6 GB 的文本权重。系统报告的可用内存比例在这次验收中从约 47% 降为 24–25%，这一指标同时受其他进程影响。进程采样另见映射文件约 5.3 GB，物理 footprint 约 552 MB，样本中的峰值约 958 MB。Metal 及文件映射占用需结合系统指标判断。不建议将应用上下文直接调到模型训练上限。4B 没有做同机对比。

启动脚本通过原生冷启动和退出验证。从脚本起动到创建应用进程约 3.3 秒。退出后脚本启动的模型服务随之停止。

全部 80 项单元及宿主测试通过。独立于真实模型的 8 项模拟验收覆盖 HTTP 503、同消息 ID 重试、取消后迟到响应和切换会话。源目录 `artifacts/chat-real-llama.json` 保存测试回复和角色顺序，`artifacts/chat-fixture.json` 为模拟记录。

可重现真实验收命令用于已经启动相同本地模型的环境。若使用启动脚本，待看到桌面应用后再运行。该命令使用独立测试用户目录。

```sh
KANSHAN_CHAT_REAL=1 KANSHAN_CHAT_PROVIDER=llama.cpp KANSHAN_CHAT_BASE_URL=http://127.0.0.1:17890 node tests/desktop-chat.integration.mjs
```
